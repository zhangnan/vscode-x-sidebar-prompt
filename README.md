## 当前需求

- 活动栏按需打开原生浏览器侧栏，不创建独立网页编辑器标签。
- 移动端视口与手机标识，尺寸随侧栏变化；X 侧栏关闭触控模拟，保留桌面鼠标与悬停。
- 编辑器字体、字号和注释色。本机固定参考为 Menlo、12px、`#8B949E`，不代表实时跟随设置。
- 图片、视频、卡片和嵌套引用媒体默认 `opacity: 0.1`；连续悬停 **2 秒**后恢复原样，移开恢复 0.1。普通媒体不再使用遮罩。
- 移除头像专用列，隐藏 emoji、名字装饰徽标、悬浮发帖按钮和“已发布”浮动条。
- 广告整帖同背景遮挡，保留占位；不响应鼠标、内部媒体不揭开、不播放。
- 普通页面保留深灰背景，“更多”菜单和弹窗单独使用不透明深色背景。
- 标题栏保留主页、刷新，移除返回；站内返回保留。
- **⌘⌥X**：其他侧栏切入 X，X 切回源代码管理；焦点在网页内也可切回。默认配置和所有现有 Profiles 均配置扩展与用户级绑定。

## 快捷键使用

| 按键 | 当前主侧栏 | 结果 |
| --- | --- | --- |
| macOS：**⌘⌥X**（Command + Option + X） | 资源管理器、搜索、源代码管理或其他侧栏 | 打开 X 浏览器侧栏 |
| 同一按键 | X 浏览器 | 切换到源代码管理 |

- 按当前显示的主侧栏判断，不要求先点击侧栏获得焦点；焦点在 X 网页内时也能切回。
- 切换仅显示/隐藏已有浏览器，不应该每次重新加载 X 首页。
- 用户级绑定覆盖默认配置和全部现有独立 Profiles；“ms工作区”是其中一个 Profile 的名称，并非只在某个业务项目生效。
- 首次安装或修改默认绑定后，可能需要重载窗口；原生桥接改变时需要完整重启。此前只声明扩展默认绑定未成功，最终改为用户级原生命令绑定并完成双向切换实测。
- 若需要换键，在 VS Code 的“键盘快捷方式”中搜索 `workbench.view.extension.mooXBrowser` 和 `workbench.view.scm`，保留按 `activeViewlet` 区分的两条条件绑定，避免同一按键永远只打开其中一个侧栏。
- 其他平台扩展默认提供 `Ctrl+Alt+X`，但本次实际安装、用户级同步和验证仅在 macOS；不要视为已完成跨平台验证。

## 实施流程

完整 Prompt 已按顺序列出十个步骤，并为每一步标明**目的、操作、完成标准**：原生基线 → 备份 → 原生侧栏 → 移动视口与鼠标 → 阅读样式 → 媒体透明度 → 广告 → 快捷键 → 生效与回归 → 文档交付。

## 验证边界

这是带代码快照的本地定制方案，**不是只安装 VSIX 就能使用的通用插件**。原生侧栏依赖指定 VS Code 版本的内部补丁。

- 原生侧栏、移动布局曾实际打开。快捷键从其他侧栏进入 X、从 X 返回源代码管理、网页获得焦点后再切回，已在当前配置文件实际验证。
- 默认配置及 13 个独立现有 Profiles 已安装扩展并写入绑定；未逐一打开所有配置实测，也不保证未来新建空白 Profile 自动继承。
- 统一透明度、两秒计时/取消、节点复用等有定向代码测试，但实际媒体类型覆盖与最终悬停表现尚未完成全面界面复验。此前嵌套缩略图多次出现遗漏，应按完整 Prompt 的清单验收。
- 一条普通视频曾在进入播放状态后提示“无法播放该媒体”，撤销强制暂停后仍失败，根因未确定。透明度修改不是播放修复。
- 广告不闪烁、弹窗背景和浮动提示等修补已写入，不能把所有规则都描述为已完成全面实测。

## 安装与隐私边界

内部浏览器接口可能随 VS Code 更新变化。修改安装目录可能触发完整性警告；不应关闭检查来隐藏警告。Prompt 要求备份、哈希核验、明确的生效方式和回退流程。

仓库包含我们编写的扩展和增量补丁，不包含完整 VS Code 程序副本、Cookie、登录数据或个人配置。
